What jekyll-seo-tag does NOT cover today, verified the same way: - og:image / og:image:width / og:image:height / og:image:alt — only emitted when a page sets `image:` front matter (ImageDrop reads page["image"] only, no site-wide fallback). No page in this site sets that today, and _config.yml has no `defaults:` image block either. - twitter:image / twitter:image:alt — same gate as above. - twitter:description — jekyll-seo-tag never emits this tag, regardless of image config; there is no branch for it in its template at all. This include supplies exactly those. The image-gated ones are wrapped in an "unless page.image" conditional so that if a future page (or a future _config.yml `defaults:` block) sets its own `image:`, jekyll-seo-tag's own per-page image handling — which can read real width/height/alt from that page's front matter — takes over automatically and this include steps aside, avoiding a future duplicate.
